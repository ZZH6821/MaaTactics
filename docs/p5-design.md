# P5 实施约束与验收清单

本文件记录原计划 P5 的可恢复混合控制约束。接口与结果分别见 [混合接口](p5-interface.md) 和 [工程验收](p5-acceptance.md)。

## 原生执行与所有权

- 完整 Copilot 增加显式 hybrid 选项，默认保留 P3 行为。
- hybrid Copilot 使用 Assistant 已有的 TacticalBattleTask，不复制 BattleHelper 状态。
- 原生安全点处理控制请求；仅在动作边界或可保存的条件等待处交出控制权。
- 未完成的输入、BulletTime 选中状态、前后延迟不允许中途转移；取消仍可打断。
- 暂停作业之后停止策略轮询和自动技能；游戏暂停作为独立的可验证操作。
- Agent 动作通过有界请求队列交给同一原生执行线程，不能排在正在暂停的 Copilot 任务后。
- 状态查询只读；只有安全暂停时允许抓图和观察，自动运行时保留互斥。

## Checkpoint 与修订

- Worker 内 checkpoint 标记 run generation、上下文 revision、作业 revision、动作序号及安全点序号。
- 保存下一动作、等待类型/费用基准、分组、部署位置、技能策略/次数/时间戳、计时与镜头信息。
- 不序列化为跨进程恢复能力；Worker 丢失、取消、换图、无法验证 UI 时拒绝恢复。
- 修订只修改未执行动作，保持原动作索引；支持跳过和原格式单动作替换，使用乐观版本校验。
- 当前条件等待动作尚未输入时可修订；恢复时只重建被修订动作的条件，不重复已完成动作。
- 未修订的条件栈和费用基准保留；作业计时冻结于交权期间，恢复时平移基准。
- Agent 动作更新同一上下文；失败使整个 checkpoint 失效，不猜测回滚。
- 恢复需要最新图片、匹配的 checkpoint/版本/会话、识别出的战斗 HUD 和明确的控制权交还。

## 必须取得的证据

1. 原生无设备测试：动作边界/条件等待接管、状态保留、策略停转、修订范围及旧版本拒绝。
2. 原生/应用竞态：请求与动作完成、resume 与输入、超时/取消/Worker 退出，不出现双控制者。
3. MCP：发现接口，暂停→观察→Agent 动作→跳过/替换→恢复，保留诚实的效果证据。
4. 实机 1-7 演习混合场景：Copilot→Agent 部署/技能/撤退→修订→恢复，最终停止清理。
5. 旧 P0–P4 测试、普通无设备 CI、补丁可复现构建、接口文档与状态更新。

自动 Ready 仍关闭；非零镜头、多地图、跨皮肤识别和 P2 十轮稳定性不在本阶段冒充完成。
